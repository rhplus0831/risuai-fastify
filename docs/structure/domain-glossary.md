# Domain Glossary

Last audited: 2026-08-29.
Targeted source check: 2026-09-12 (ownership probe, diagnostics, and intermediate-display routing).

This file defines shared names and points to cross-layer owners. Detailed
behavior belongs in the focused document linked from [`README.md`](README.md).
Terms belong here when they cross storage, runtime, or UI ownership boundaries;
component-only behavior stays in the nearest focused guide.

## Domain Data

| Term | Meaning |
| --- | --- |
| Database compatibility shape | `Database` in `src/ts/storage/database.svelte.ts`: the canonical serialized compatibility shape used by browser code and server helpers. Live state is composed from API resources; it is not one mutable browser database. |
| Character | Bot/character participant keyed by `chaId`, with prompts, chats, lorebooks, scripts, modules, media, and settings. `Message.role === "char"` means the assistant speaker. |
| Chat | Conversation owned by one character, with metadata, script/lorebook state, memory metadata, generation settings, and separately stored messages. |
| Pinned chat | Durable per-chat metadata that projects a stable bot/chat shortcut into the narrow sidebar rail. |
| Message | Ordered row in SQLite `messages`; commands append, update, truncate, delete, replace a tail, or persist generation output. |
| Reroll alternate | Displaced or candidate message stored in SQLite `messages` with `alternate = 1` and hydrated with its active chat. It is not a separate browser record type. |
| Chat folder | Character-owned grouping metadata for chats. |
| Chat generation settings | Per-chat persona, model preset, prompt preset, Agent Preset, Saved Toggles link, jailbreak, and sidebar overrides used by send, preview, continue, and regenerate. |
| Saved Toggles preset | `ChatGenerationTogglePreset`: named snapshot of sidebar values and toggle kinds. A chat/loadout may retain its id while active values are matched, edited, mismatched, or unlinked. |
| Composer modes | `fixedChatTextarea` chooses dock versus in-flow placement; `floatingChatInput` permits temporary floating presentation in in-flow mode. Draft ownership and viewport behavior: [Composer layout](../../src/docs/svelte-chat-ui.md#composer-layout-modes-and-mobile-viewport). |
| Memory settings category | Current user-facing name for the settings page formerly labeled Media. It contains long-term-memory, TTS, and image-generation controls; `media` remains valid only for assets and provider operations, not the category name. |
| Settings group | Named settings resource/command slice. `agents` and `models` are read-only slices with dedicated commands; prompt fields use `prompt`. |
| Model profile | Reusable provider/model/options/runtime/fallback record that may reference a shared provider credential. `modelProfileOrder` may interleave UX-only dividers, which never participate in resolution or execution. |
| Provider credential | Stable-id reusable API-key or Vertex-service-account row. Profiles reference `providerOptions.credentialId`; reads mask secrets and deletion is blocked while referenced. |
| Model role profile | Binding for `chatMain`, `chatAux`, `memory`, `emotion`, `translate`, `otherAx`, `scriptMain`, or `scriptAux`; it may select a profile, inherit, or use compatibility data. |
| Model runtime defaults | Shared runtime options applied before profile-specific overrides, including `halfStreaming` and the inheritable `stripCoT` transform. Provider adapters may derive wire fields such as Gemini `thinkingLevel`; it is not a top-level record. |
| Model preset | Stable-id, chat-selectable snapshot of model-role bindings. Imported/older rows may retain embedded profiles, runtime defaults, and compatible flat model fields. |
| Legacy bot preset | Unsplit model-and-prompt compatibility/import row retained for older saves and explicit extraction. |
| Prompt preset | Modern stable-id prompt owner with ordered prompt items and an optional template. Archived rows remain referenceable; archive state changes list visibility rather than ownership. |
| Prompt template | Ordered description/persona/lorebook/memory/history/author-note/custom item body owned by a modern prompt preset. Optional `role2` selects the rendered role for supported blocks; `Database.promptTemplate` is a compatibility projection. |
| Agent | Reusable auxiliary-generation behavior: instruction with optional role-tagged ChatML mode, prepared-input scopes, configurable toggles, named Agent-only lorebook inputs, output format, and model/runtime defaults. |
| Agent Preset | Reusable before-main/after-main pipeline selected per chat or through the global default. Each use owns phase, dependencies, output/destination, failure policy, and overrides; the preset may add a module overlay and CBS final-output template. |
| Input hook | Stable-id `draft` or `btw` prompt that inherits `otherAx` or selects a model profile. It supports filtered, token-bounded 1-50 message slots; a draft hook may retain the original composer text as the sent message translation. |
| Persona | User profile selected globally or per chat and mirrored into legacy fields where required. |
| Loadout | Selectively applicable bundle of preset/profile, persona, module, global-variable, and chat-generation settings. `characterIds` records recent use; applying a loadout does not navigate. |
| Lorebook | Stable-id world-info entries attached globally or to a character, chat, or module. Agent-only entries are named Agent inputs and never participate in normal prompt activation. |
| Module | Reusable package of lorebooks, scripts, triggers, configuration, assets, and optionally an MCP identifier. |
| Module folder | Durable presentation grouping: `moduleFolders` in the `modules` settings group plus `folderId` on module rows. It does not participate in activation. [Organization ownership and lifecycle](plugins-and-mcp.md#module-organization). |
| MCP module | Special module row for a browser-executed MCP endpoint. Direct and `.risum` creation, global enablement, and durable deletion are supported; general edit/export/scoped linking excludes it. |
| Script / trigger definition | Regex/replacer script or Lua/trigger row owned globally, by a character, or by a module. |
| Plugin | V3 browser-executed extension record. Fastify persists records/custom storage but never executes plugin code; exact-script permission grants are device-local. |
| Plugin custom storage | One global key/value JSON map persisted in SQLite `plugin_custom_storage`; plugins must namespace their keys. Device-local storage is a separate compatibility/cache surface. |
| Translator preset | Saved one-to-five-step translation pipeline with per-step model profile/inheritance, named outputs, prompt slots, and `.risutl` import/export. |
| Greeting translation | Durable `greeting_translations` row identified by character id, greeting index, and settings hash. Its `source_hash` rejects stale source text; translations are also carried in portable character data. |
| Hypa V3 preset/data | Memory preset collection plus per-chat compatibility metadata in `chat_hypa_v3`; maintained data lives in `memory_chunks`, `memory_summaries`, `memory_embeddings`, and `memory_jobs`. |
| BardWiki memory | Server-owned per-chat Markdown documents, immutable versions, exact-source receipts, durable background jobs, derived lexical/link projections, and explicit vault/rebuild workflows. |
| Asset | Content-addressed binary with SQLite metadata and bytes under `data/assets/`. Static app sources under `public/` and `src/etc/` are separate. |
| Inlay catalog entry | Revisioned metadata keyed to an authoritative asset: name, aliases, dimensions, and joined media type/size/extension. The browser owns a standalone root projection. |
| Push subscription | Operational Web Push row. VAPID keys come from environment or `data/__web_push_vapid_keys.json`; the browser worker handles chat-completion notifications. |
| LLM request history record | Operational `request_history` row for a provider attempt: status, profile snapshot, prompt/context, response, timestamps, and sanitized API metadata. Reads derive `durationMs`; retention is bounded by `requestHistoryLimit`. |
| `.risu` save | Portable save envelope covering current block saves, legacy envelopes, bundles, and local-backup compatibility. Whole-database exports can contain raw provider credentials and must be treated as secrets. |
| RisuRealm character | Realm-hosted dynamic card or `charx` imported server-side with bounded conversion, progress, assets, and one revisioned character commit. |
| Legacy storage byte store | Compatibility `/api/v1/storage/*` bytes under `data/save/`; distinct from SQLite domain state. |

## Runtime Contracts

| Term | Contract and primary owner |
| --- | --- |
| Database lineage | Persistent database identity in `database_metadata`; scopes receipts, outbox intents, and recovery drafts and rotates on destructive replacement. |
| Revision | Global optimistic-concurrency counter in `server/fastify/src/db.ts`; ordinary command transactions check a base, write domain state/event, and bump it once. |
| Command mutation | Revision-checked SQLite write implemented by `server/fastify/src/commands/mutations.ts` and route/domain helpers. |
| Durable mutation intent / outbox | AES-GCM browser journal staged by `src/ts/server/pendingMutationOutbox.ts` and `src/ts/server/durableMutationDispatch.ts`. It replays current-scope intent before hydration; it is not server truth. |
| Recovery draft | Lineage/writer-scoped browser editing record: bounded plaintext composer `sessionStorage` or separate encrypted module IndexedDB. It is neither outbox intent nor acknowledgement. |
| Persistence activity | Browser-only saving signal in `src/ts/server/persistenceActivity.svelte.ts`, active through queued reconciliation and current-writer outbox retention. Feedback, not proof of server acceptance. |
| Server mutation receipt | Lineage-scoped SQLite idempotency record in `server/fastify/src/commandMutationReceipts.ts`, committed with original revision/event/result and acknowledged after browser intent removal. |
| Compact local-effect acknowledgement | Response proof checked by browser command/local-effect/resource fences. It may accept already-visible optimistic state without a GET; it is neither an outbox row nor server receipt. |
| Command event / invalidation | Replayable `command_events` row whose defaults live in `server/fastify/src/commands/events.ts` and whose current/compatibility keys map to REST reads in `src/ts/server/resourceInvalidation.ts`. Unknown or underspecified events force broad recovery. |
| API-backed resource state | Explicit browser settings, collection, character, chat/transcript, lorebook, prompt-template, and standalone feature owners. `composeResourceDatabaseSnapshot()` is a detached interchange/diagnostic/test materializer, not production reactive state. |
| Resource read / hydration | Authenticated root/slice/body reads wrapped by `src/ts/server/resourceReads.ts` and `src/ts/server/hydrationReads.ts`; shell resources omit large owner bodies until needed. |
| Disposable resource cache | SHA-256 value/manifest IndexedDB reused only after an authenticated server hash match. Safe to discard and never offline state. |
| Projection epoch | Client-only monotonic freshness fence in `src/ts/server/resourceState.svelte.ts`; the historical name does not imply a live `/projection` API. |
| Active writer | Durable single-writer lease in `server/fastify/src/activeWriter.ts` and `server/fastify/src/databaseLineage.ts`, carried as `risu-writer-session`. Read-only bootstrap/resources/events do not require it. |
| Ownership probe | Authenticated no-store `GET /api/v1/ownership` returns the versioned durable database-lineage and writer tuple without acquiring ownership. Shared page lifecycle evidence may trigger it, while each recovery domain owns request sequencing; unchanged authority can resume a healthy projection and changed/uncertain authority enters fenced recovery. |
| Provider secret | Raw shared/legacy credential masked by `server/fastify/src/providerSecrets.ts` on resource reads and resolved server-side for generation or fixed provider/media operations. One-shot raw drafts exist only where a protocol permits them. |
| Provider capability table | Pure supported/unsupported routing verdict in `packages/shared-core/src/providerCapability.ts`. |
| Strip CoT | Effective model-runtime option that routes completion frames through `server/fastify/src/generation/stripCoT.ts`, removing known reasoning blocks before downstream consumers and request-history recording when enabled. |
| Half-streaming | Effective global/profile generation mode that requests provider streaming while buffering displayed text; server token-progress events keep browser throughput feedback live. |
| OpenAI Flex processing | Persisted `openAIFlexProcessing` provider setting that adds `service_tier: "flex"` only for supported official OpenAI requests in both browser and Fastify dispatch. |
| Server prompt assembly | Supported chat path through `src/ts/process/request/serverPromptAssembly.ts` and `server/fastify/src/prompt/assemble.ts`; unsupported shapes hard-fail. |
| CBS / history window | RisuAI's shared `{{...}}` template syntax registered in `src/ts/cbs.ts`. Numeric `{{history::N}}`/`{{messages::N}}` yields raw text from the newest `N` stored rows chronologically without the greeting; unnumbered `{{history}}` serializes the full history and includes it. |
| Generation operation | SQLite-backed, lineage-scoped send/continue/regenerate intent and numbered-attempt state in `server/fastify/src/generationOperations.ts`; acceptance, cancellation, retry, result identity, and honest restart recovery survive the process-local runner. |
| Generation job | Process-local provider runner and replay window in `server/fastify/src/generationJobs.ts`, bound to one generation-operation attempt. It supports detach/reattach during that server lifetime; restart reconciliation marks interrupted attempts for explicit recovery. |
| Generation effect ledger | SQLite claim/lease/receipt state for durable, ephemeral, and recomputed completion effects. `server/fastify/src/generationEffects.ts` and `src/ts/process/generationEffectLedger.ts` prevent duplicate live or late-recovery execution. |
| Generation finalization retry | SQLite operational row that retries idempotent result persistence after process or target-write failure; distinct from the process-local generation job. |
| `activeGenerationJobs` | Runtime-only bootstrap list of running durable jobs, including mode and regenerate target where relevant. |
| `activeMessageTranslations` | Runtime-only bootstrap list of running and bounded recent terminal transcript-message translation work. |
| `activeGreetingTranslations` | Runtime-only bootstrap list of running plus recent succeeded/failed greeting translations from the separate registry; terminal rows are retained for 10 minutes and capped at 128. |
| LLM request history | Durable operational SQLite state outside global revision/events; provider attempts write/finalize/prune it best-effort and authenticated APIs read/delete it. |
| Memory job/event | Durable `chunk`, `embed`, or `summarize` job with live, non-replayable `memory.job` progress; it does not bump the domain revision. |
| BardWiki receipt/job | Exact-source confirmation receipt plus a durable `apply_turn`, `reconcile_receipt`, or `rebuild_chat` job. Domain publication is revisioned; bounded `bardwiki.job` progress is live-only operational state. |
| Context truncation acknowledgement | Durable per-chat `hypaContextTruncationAcknowledged` confirmation. Despite the historical field name, Fastify requires it before persistence modes omit older context when Hypa V3 is not active; the browser persists it before retrying generation. |
| Server Lua VM | Wasmoon runtime under `server/fastify/src/prompt/luaRuntime.ts` for supported non-interactive hooks. |
| Post-generation pass | Output triggers, `editOutput`, script-state/transcript derivation, automatic generated-message translation, and progress under `server/fastify/src/prompt/`, `server/fastify/src/translation/`, and `server/fastify/src/routes/generationChat.ts`. |
| Stable domain identity | Public command APIs use stable ids rather than array indexes; reorder commands validate complete owner-scoped id lists. |

## Retired And No-Port Vocabulary

| Term | Status |
| --- | --- |
